# ADR-002 — `sos-ingest` is a separate binary with its own deploy and its own durability

Status: Accepted · 2026-08-04 · derives from ADR-001

## Context

You will ship a bug to the control plane. It is a rich service that changes
weekly: consent, journeys, drills, after-action reports, policy. The endpoint
that accepts an emergency must not be inside it, because "the control plane is
down" and "nobody can raise an alarm" have to be two different sentences
(PRD §4.5, docs/02 §2.5.1).

## Decision

`sos-ingest` is its own binary, its own container image, its own build pipeline
and its own rollback. It shares nothing with the control plane except a
directory on disk.

Enforced properties, not intentions:

- **≤1000 source lines.** `TestLOCBudget` in `backend/cmd/sos-ingest/main_test.go`
  counts non-blank non-comment lines of `main.go` and fails the build over
  budget. The `ops/docker-compose.yml` build for this binary runs that test
  *inside the image build*, so an over-budget ingest cannot be deployed even by
  someone who skipped CI.
- **No DB read on the request path.** Family and device-key lookups come from
  in-memory caches; the projector that fills them runs off the hot path.
- **Its own write-ahead log.** `backend/internal/wal/wal.go` is fsynced *before*
  any 2xx is written. Durability does not depend on the control plane, on a
  database, or on anything a bad deploy can remove.
- **No `depends_on`.** Its compose block must come up and accept an SOS with
  every other service in the file dead.
- **≤2 deploys per year** is the budget the above exists to protect.

## Alternatives

**An endpoint inside the monolith** — rejected. Same process, same deploy, same
blast radius. The isolation would exist only as a promise about where people put
their code.

## Consequences

- Anything the emergency path *would* like — a policy lookup, a consent check, a
  nicer error — has to be argued past a 1000-line ceiling, and the honest answer
  is usually "put it in the control plane and let ingest stay stupid".
- Two binaries means two copies of the small things: config parsing, logging
  setup, the envelope decoder's call sites. That duplication is the price.
- The shared bus directory is the one seam left, and it is a real coupling: if a
  downstream consumer corrupts `bus/stream.wal`, ingest's publishes go into a
  file that nobody can read. The WAL's torn-tail truncation (`wal.Open`) bounds
  the damage; it does not eliminate the shared surface.
- The LOC budget will eventually be reached. When it is, the failure mode is a
  build error and an argument — which is the point — not a quietly fattening
  critical path.

## Implementation

- `backend/cmd/sos-ingest/main.go` — the binary
- `backend/cmd/sos-ingest/main_test.go` — `TestLOCBudget`, budget 1000
- `backend/internal/wal/wal.go` — fsync-before-2xx, CRC-framed, torn-tail safe
- `backend/internal/store/store.go` — explicitly not touched on the request path
- `ops/docker-compose.yml` — separate Dockerfile, no `depends_on`, 2× healthcheck
  frequency
- `mobile/metro.config.js` — the client mirror of the same idea: a release must
  be able to ship without the crypto module and still send
