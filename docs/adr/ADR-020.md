# ADR-020 — The SMS payload is pure ASCII English

Status: Accepted · 2026-08-04

## Context

The whole app is localised into Gujarati and Hindi, because a family that cannot
read the interface cannot use the system (PRD §1.7 C5). The SMS transport is the
one place where that instinct is wrong.

A GSM-7 SMS holds 160 characters. **One** Devanagari or Gujarati character
converts the entire message to UCS-2 and cuts the limit to **70** (PRD P-033).
The payload budget — protocol tag, incident prefix, name, trigger code,
coordinates, accuracy, battery, timestamp, signature, separators, and a
human-readable tail — comes to about 154 characters. At 70 it does not fit, so
the message either splits into concatenated parts that can arrive out of order
and partially, or it drops the coordinates. SMS is the transport that carries
the emergency when everything else has failed; it is the wrong place to be
clever.

## Decision

The SMS payload is pure ASCII, English, ≤160 characters. Names are
transliterated (`Priya`, not `પ્રિયા`). Every byte is in the range 32..126, and
a unit test asserts it.

This is the one documented exception to the localisation rule, stated in
`mobile/src/i18n/index.ts` where a translator will actually see it.

Because carriers strip and filter links, the tail **repeats the coordinates as
plain text** — the raw lat,lon pair is the payload, a link is only a convenience
(P-051).

## Alternatives

**Localised SMS** — rejected. It is the kinder-looking option and it costs 90
characters of an emergency message.

## Consequences

- The family member most likely to be reached by SMS — an older relative on a
  feature phone, in a rural area, on 2G — may be the one least comfortable
  reading English. That is the cost, it lands on the person the fallback exists
  for, and there is no way to pay it in characters.
- Mitigations are structural rather than linguistic: the trigger is a
  three-letter code, the coordinates are digits, and the name is transliterated
  so it is at least pronounceable. Someone who cannot read the sentence can
  still recognise a name and a number.
- Names must be unique per family, or "PRIYA NEEDS HELP" is ambiguous at the
  moment it matters (F-18). That constraint exists because of this decision.
- Transliteration is a lossy, one-way transform of somebody's name, applied at
  onboarding. It has to be shown to them then, not chosen silently.

## Implementation

- `mobile/src/t0/smsPayload.ts` — the encoder, the character budget, the
  three-letter trigger codes, the coordinate-repeating tail
- `mobile/src/i18n/index.ts` — the stated exception to localisation
- `mobile/app/(tabs)/settings.tsx` — short-name uniqueness (F-18)
- `mobile/test/invariants.test.ts` — invariant I-2: pure ASCII, ≤160
- `backend/internal/envelope/crosslang_test.go` — the payload still decodes,
  stays ASCII and stays ≤160 after crossing into Go
