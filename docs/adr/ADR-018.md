# ADR-018 — The safety path fails OPEN

Status: Accepted · 2026-08-04 · ★ deliberate inversion of standard security doctrine — do not "fix" it

## Context

Standard security doctrine says fail closed: if you cannot verify it, reject it.
Applied to an emergency path that doctrine says "this envelope's signature does
not verify, so discard it" — and the thing being discarded is somebody's SOS.

The asymmetry is total. A false alarm costs a phone call. A suppressed real
alarm costs a life (PRD §4.5, P-007, P8).

## Decision

On the safety path, accept and flag. Never reject, never drop, never throw.

- **`sos-ingest`** accepts an envelope whose signature fails and marks it
  `FLAG_UNVERIFIED`. Same for an unknown device key, and the same for inbound
  SMS.
- **A tampered SMS still decodes**, flagged, never dropped.
- **A missing state-machine guard evaluates to TRUE.** The generated machine
  fails toward escalating, not toward stalling.
- **No function in `mobile/src/net/api.ts` rejects.** Every failure — 401, 413,
  DNS, timeout — is returned as data, because the caller's next line is "fan out
  over the remaining transports".
- **A throwing consumer must never stop the sensor pipeline**, a throwing timer
  must never leave an incident stuck, and a pulse that throws must never end the
  foreground agent.

The inversion is bounded, not unlimited (R5, F-04): fail-open is scoped to known
families, limited per **family** rather than per device, and excess is
**coalesced, not dropped**.

Two places invert the inversion, on purpose:

- The **client envelope builder fails CLOSED when it cannot pad** to the fixed
  size. An unpadded envelope leaks duress by length (F-01, threat T4); sending a
  smaller-but-working envelope would be worse than sending none.
- The **camera node fails closed on privacy** (`mobile/src/state/nodeStore.ts`):
  no key, no camera. A missed alarm risks one life; a leaked archive of a home's
  interior harms everyone who lives there.

## Alternatives

**Fail closed** — rejected here and only here. It remains correct for the
control plane, for consent (`Check` denies if it cannot write the access log)
and for everything that is not carrying an emergency.

## Consequences

- **Anyone who can reach the endpoint with a known family id can raise an
  alarm.** That is not a bug report; it is the cost of the decision, and F-04 is
  the reason it is bounded per family and coalesced rather than left as an
  unbounded flood vector.
- The signature layer can silently stop doing anything. If the client and server
  canonicalise differently by one byte, every genuine incident is accepted and
  flagged `UNVERIFIED`, nothing errors, nothing pages, and no dashboard shows
  it. `backend/internal/envelope/crosslang_test.go` exists specifically because
  fail-open makes that failure invisible.
- `UNVERIFIED` must reach a human or the flag is decoration: the fan-out carries
  a warning banner rather than treating a flagged incident as clean.
- Fail-open is easy to "correct". Any future reviewer will read
  `if !verified { accept }` as a bug. That is why this ADR exists and why the
  citation is repeated at each of the ~20 sites that implement it.

## Implementation

- `backend/cmd/sos-ingest/main.go` — accept-flag-count on bad signature; the
  same for SMS
- `backend/cmd/sos-ingest/main_test.go` — asserts a bad signature is flagged,
  not rejected, over both transports
- `backend/internal/envelope/envelope.go` — the client-fails-closed /
  server-fails-open asymmetry, stated at the top
- `mobile/src/net/api.ts` — no function rejects; `FLAG_UNVERIFIED`
- `mobile/src/t0/stateMachine.generated.ts` — a missing guard is TRUE
- `mobile/src/t0/smsPayload.ts` — a false HMAC tag is flagged, never dropped
- `mobile/src/t0/pocketSuppressor.ts` — suppression is the inverse and is
  bounded accordingly
- `mobile/src/t0/fusion.ts`, `triggerRouter.ts`, `mobile/modules/kavach-t0/.../KavachForegroundService.kt`,
  `BootReceiver.kt` — throwing consumers never stop the plane
- `mobile/test/invariants.test.ts` — "a tampered SMS still decodes, flagged
  unverified — never dropped"
- `mobile/src/state/nodeStore.ts` — the deliberate privacy-side inversion
