# ADR-001 — Separate the system into three planes by criticality

Status: Accepted · 2026-08-04 · foundational; ADR-002, ADR-011, ADR-015 and ADR-018 all follow from it

## Context

Safety systems fail because the path that carries the emergency is wired to the
path that carries everything else. An auth refresh, a config fetch, a database
migration, a crashed UI — none of them are emergencies, and all of them sit
between the trigger and the alert in a single-tier design. PRD §4.5 names this
the dominant failure mode of the category.

## Decision

Three planes, separated by how bad it is when each one is down.

| Plane | What it is | Allowed to be down |
|---|---|---|
| **T0** | Native survival plane: trigger → state machine → alarm → transport fan-out | Never |
| **T1** | The app: screens, sync, consent UI, maps, journeys | Yes, for hours |
| **T2** | Backend: control plane, escalation, notification, realtime | Yes, for hours (except `sos-ingest`, see ADR-002) |

Two structural rules make the separation real rather than aspirational
(docs/02 §2.1, R2 and R7):

- T0 → T1 is fire-and-forget. No code path in the trigger sequence awaits a
  network result.
- There is **no** method by which T1 can block, veto, delay or gate a T0 action.
  T1 may *request* a trigger; it can never suppress one.

T0 additionally runs in its own OS process (`:t0`, docs/02 §2.2.1), so an
out-of-memory kill of the app process does not take the agent with it.

## Alternatives

**Single-tier app** — rejected. It is the design in which every non-critical
dependency becomes a critical one, and the coupling is invisible until the
moment it matters.

## Consequences

- Every T0 capability exists twice: once in Kotlin (`mobile/modules/kavach-t0/`)
  and once in TypeScript (`mobile/src/t0/`) for the degraded fidelity that runs
  when the native module is absent. Two implementations of the same behaviour is
  a permanent maintenance tax and a permanent divergence risk.
- The process split is not free: the JS side reaches Kotlin **by name**, and a
  rename is invisible to both compilers. `mobile/test/native-bridge.test.ts`
  exists solely because that drift would otherwise be discovered during a real
  emergency.
- Because T1 cannot gate T0, a false trigger cannot be suppressed by the UI
  either. That cost is accepted deliberately and is bounded elsewhere —
  `mobile/src/t0/pocketSuppressor.ts`, the cancel window, PROBE.
- Splitting into `:t0` means `MainApplication` is created in both processes.
  Without a guard the agent carries the whole React Native runtime; see
  `mobile/plugins/withKavachT0Process.js` and DELIVERY.md §2 defect 4.

## Implementation

- `mobile/modules/kavach-t0/android/src/main/AndroidManifest.xml` — `:t0`
  process declaration, `directBootAware`, boot and shutdown receivers
- `mobile/modules/kavach-t0/android/src/main/java/expo/modules/kavacht0/KavachForegroundService.kt`
- `mobile/plugins/withKavachT0Process.js` — keeps RN out of the `:t0` process
- `mobile/src/t0/` — the JS mirror: `triggerRouter.ts`, `dispatcher.ts`,
  `stateMachine.generated.ts`, `alarm.ts`, `blackbox.ts`
- `backend/cmd/sos-ingest/main.go` — the server-side end of the T0 path
- `docs/02-System-Architecture.md` §2.0–§2.2
